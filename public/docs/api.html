Wavadesk API

Wavadesk is a multi-tenant WhatsApp customer support platform. This API lets you control everything that happens in the dashboard programmatically — connect WhatsApp numbers, manage conversations, send messages, configure AI auto-reply, and more.

All API endpoints are under https://wavadesk.com/api/. Authentication uses Bearer tokens — no cookies or CSRF tokens required.

Authentication

Every request (except login) requires a Bearer token in the Authorization header. Get your token by calling the login endpoint once.

Step 1 — Login

POST /api/auth/login
Content-Type: application/json

{
  "email": "admin@yourcompany.com",
  "password": "your-password"
}

Response:

{
  "token": "1|abc123xyz...",
  "user": {
    "id": 8,
    "name": "Ahmed Admin",
    "email": "admin@yourcompany.com",
    "role": "admin"
  }
}

Step 2 — Use the token

Add the token to every subsequent request:

Authorization: Bearer 1|abc123xyz...
Accept: application/json
Tokens do not expire automatically. Call POST /api/auth/logout to revoke a token when done.

How the Dashboard Works

The dashboard follows a simple 3-step flow. Understanding this helps you replicate any dashboard action via the API.

Connect WhatsAppCreate instance → Scan QR
→
Receive ConversationsWebhook → inbox pool
→
Agent Claims & RepliesClaim → send messages
→
CloseResolve or reassign

1. Connect a WhatsApp Number

Each WhatsApp number is called an Instance. You create one in the dashboard, scan a QR code to link it to a WhatsApp account, and it becomes the channel through which customers contact you.

Via API:

  1. Call POST /api/instances to create the instance record.
  2. Call POST /api/instances/{id}/connect — the response contains a qr_code (base64 image).
  3. Display that QR to the user to scan with their WhatsApp app.
  4. Poll GET /api/instances/{id}/status every few seconds until status becomes connected.

Instance statuses:

connected — linked and receiving messages
connecting — waiting for QR scan
disconnected — logged out or unreachable

2. Conversations

When a customer sends a WhatsApp message to your connected number, the system automatically creates a Conversation in the pool (unassigned inbox). Agents then claim conversations to handle them.

You can also start conversations outbound — dial out to any WhatsApp number using POST /api/conversations/start.

Conversation states:

pool — waiting, not yet assigned to any agent
claimed — assigned to and being handled by an agent
closed — resolved

Typical agent workflow via API:

// 1. Get conversations waiting in the pool
GET /api/conversations?tab=pool

// 2. Claim one
POST /api/conversations/{id}/claim

// 3. Read the message history
GET /api/conversations/{id}/messages

// 4. Reply
POST /api/conversations/{id}/messages
{ "type": "text", "body": "Hello, I can help you!" }

// 5. Close when done
POST /api/conversations/{id}/close

3. Messages

Messages can be text, images, documents, audio, or internal agent notes. Outbound messages are dispatched asynchronously — the API returns immediately and the message is delivered in the background.

Message status lifecycle:

pendingCreated, not yet sent
→
sentDelivered to WhatsApp
→
readCustomer opened it

If delivery fails: status becomes failed.

Instance Endpoints

Manage WhatsApp numbers connected to your account. Requires role admin or super_admin.

GET /api/instances List all instances

Returns all WhatsApp instances for your tenant with summary stats.

{
  "data": [
    {
      "id": 10,
      "name": "Support Line",
      "status": "connected",
      "phone_number": "21627541269",
      "team_id": 3,
      "gateway_instance_id": "wa-4-10",
      "webhook_enabled": true
    }
  ],
  "stats": {
    "connected": 1,
    "connecting": 0,
    "disconnected": 0
  }
}
POST /api/instances Create a new instance
FieldTypeRequiredDescription
namestring✓Display name (max 100 chars)
team_idinteger—Assign to a specific team
POST /api/instances
{ "name": "Sales Line", "team_id": 3 }

Returns the created instance with status disconnected. Call /connect next to get the QR code.

POST /api/instances/{id}/connect Get QR code to link WhatsApp

Returns a base64 QR code image. Display it to the user — they scan it with their WhatsApp app to link the number.

{
  "qr_code": "data:image/png;base64,iVBORw0KGgo...",
  "status": "connecting"
}
If the instance is already connected, the response returns "status": "connected" and no QR.
If QR is null, the gateway instance is stuck. The API will automatically restart it and return a fresh QR.
GET /api/instances/{id}/status Check connection status

Fetches live status from the WhatsApp gateway and syncs the phone number.

{
  "status": "connected",
  "qr_code": null,
  "instance": { "id": 10, "phone_number": "21627541269", ... }
}

Poll this every 3–5 seconds after /connect until status is connected.

POST /api/instances/{id}/disconnect Disconnect from WhatsApp

Logs out the WhatsApp session. The instance record stays in your account — call /connect again to reconnect.

{ "message": "Instance disconnected." }
DELETE /api/instances/{id} Delete instance permanently

Disconnects from WhatsApp and permanently deletes the instance record. This cannot be undone.

{ "message": "Instance deleted." }

Conversation Endpoints

Available to all roles (admin, supervisor, agent). Subscription required.

GET /api/conversations List conversations

Query parameters

ParameterValuesDescription
tabmine / pool / all / closedFilter by state and ownership
searchstringSearch by customer name, phone, or last message
team_idintegerFilter by team
instance_idintegerFilter by WhatsApp number
per_page1–100 (default 25)Results per page
pageintegerPage number
GET /api/conversations?tab=pool&per_page=10

Returns a paginated list. Each conversation includes the customer, instance, team, and ownerAgent.

POST /api/conversations/start Start an outbound conversation

Verify a phone number on WhatsApp, create a conversation, and send the first message — all in one call.

FieldTypeRequiredDescription
instance_idinteger✓Which WhatsApp number to send from
phonestring✓Recipient phone (digits only, e.g. 21612345678)
messagestring✓First message text (max 4096 chars)
POST /api/conversations/start
{
  "instance_id": 10,
  "phone": "21612345678",
  "message": "Hello! How can we help you today?"
}
Returns 422 with "code": "number_not_on_whatsapp" if the number is not registered on WhatsApp.
Returns 422 with "code": "instance_not_connected" if the instance is not connected.
POST /api/conversations/{id}/claim Claim a conversation

Assigns the conversation to the authenticated agent. Moves it from pool to claimed. No body required.

POST /api/conversations/{id}/release Release back to pool

Un-assigns the conversation and returns it to the pool so another agent can take it. No body required.

POST /api/conversations/{id}/reassign Reassign to another agent
FieldTypeRequiredDescription
agent_idinteger✓ID of the agent to assign to
POST /api/conversations/43/reassign
{ "agent_id": 5 }
POST /api/conversations/{id}/close Close a conversation

Marks the conversation as resolved. No body required. Use /reopen to reactivate it.

POST /api/conversations/{id}/toggle-ai Enable / disable AI auto-reply

Toggles AI auto-reply on or off for this specific conversation. No body required.

{ "ai_enabled": true }
DELETE /api/conversations/{id} Delete conversation permanently

Deletes the conversation and all its messages. This cannot be undone.

FieldTypeRequiredDescription

Upload a file and get back a URL to use in the media_url field of a message. Use multipart/form-data.

FieldDescription

Roles & Permissions

Each user has one role. The role determines which endpoints they can access.

RoleCan access
super_adminEverything — across all tenants
adminInstances, conversations, messages, AI settings, users, teams
supervisorConversations (all in their teams), reassign, close, reports
agentConversations assigned to their teams, claim, reply, close own conversations
Agents and supervisors only see conversations from teams they belong to.

Webhooks (Inbound)

When a customer sends a WhatsApp message to your connected number, the gateway forwards it to Wavadesk via a webhook. This is handled automatically — you do not need to configure anything.

The webhook URL per instance is:

https://wavadesk.com/api/webhooks/whatsapp/{webhook_token}

The system then:

  1. Creates or finds the customer record by phone number.
  2. Creates or finds an open conversation for that customer.
  3. Stores the inbound message.
  4. Notifies online agents in real-time.
  5. Triggers AI auto-reply if enabled for that conversation.
No action needed on your side for inbound messages — just keep the instance connected and the webhook will handle everything.
